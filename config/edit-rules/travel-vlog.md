# 旅行VLOG剪辑规则

流程：正文粗剪 → 人工精剪 → 片头文本结构（选片＋旁白）→ 片头交互剪辑 → 按需补旁白 → 字幕与收尾。

## 初版剪辑框架

1. 读取理解本集范围内的编年史，生成剪辑框架文本，按天、重点时间、行车、航拍和关键事件组织。使用`SubAgent`，切分按照天，但不是每天一个，而是按照150个事件左右为阈值拆分几天是一个包！
2. 素材必须大致按照时间顺序排列，但是行车部分有额外规则：
    1. 行车部分，由于包含口播部分/第一视角行车/无人机跟车，所以可能需要按照节奏，进行更合理的编排，比如如果同时有无人机跟车和非口播行车素材在一个时间窗口重复，优先使用无人机跟车素材
    2. 行车之外，同一个事件中不同类型的视频，航拍要聚在一起排列插入在普通视频之中，照片要聚在一起排列在最后
3. LLM生成文本稿件，之后交给人工审查：
    1. 稿件参考文档末尾的附录`附录-剪辑框架模板`
    2. 条目尽可能详细，但主表必须便于人工审查：`事件 / 时间 / spans / 叙事` 只写人能快速判断的素材概况，不写代表 spanId、不重复 eventId/routeId/source window 等证据索引，也不写任何具体素材主键
    3. `spans`列必须写可审查的素材类型数量和视频语音拆分，格式参考：`共28段：行车13（有语音5/无语音8）、航拍7、普通视频4（有语音2/无语音2）、照片4`；不能写“高密度素材组 / 多段 / 少量 / 含口播”这类模糊概括
    4. `叙事`列只写素材的客观画面/声音总结，不写“保留 / 优先 / 插入 / 加速 / 静音”等后续剪辑指导
    5. `全片章节`只做宏观概览，`分段操作稿`是给 material.recall 的唯一分段 handoff；不要另写`beat 边界索引`
    6. 尽可能将有效片段添加，不要擅自过多剔除

## 交互式粗剪

1. 根据剪辑框架的定稿，进入素材召回阶段：
    1. 使用`SubAgent`，切分按照天数粒度，但不是每天一个，而是按照2000个span左右为阈值拆分几天是一个包！
    2. 当遇到口播和纯视觉窗口的重叠时，优先选择口播窗口
    3. 源于同一个原始素材的，没有口播的行车Span，首先要按照画面语义去重，然后只能最多保留三段
    4. 所有没有口播的行车类型Span，直接静音
    5. 超过5秒的静音行车片段，通过整数倍加速压到10秒之内，最大倍率四倍，如果脚本无法实现，就试试ComputerUse，反正已经分好颜色组了
2. 根据最终结论，在达芬奇剪辑工程内，生成对应的时间线
3. 根据当前时间线，根据已有的口播字幕映射出一个SRT，供用户导入，辅助剪辑
4. 人工和LLM针对时间线，交互式修改，直到正文基本定稿，人工确认后，进入短片头设计

## 短片头

### 1. 读取当前正文，确定引子

1. 人工确认正文基本完成后，读取目标 Resolve 时间线当前实际保留的片段、源素材范围和字幕，核对本集范围与已移出的内容。旧剪辑框架、旧粗剪审计不能代替当前精剪正文。
2. 从实际入选内容中提炼本集特点，兼顾风光高点、现场发现、人物反应和有趣经历；片头可以跨时间精选、复用正文素材，正文仍遵循真实经历顺序。
3. 结合用户的实际感受确定引子，例如“来之前的印象 → 到达后的新发现”。不能替用户编造原有印象，也不要求每集都使用反转句式。用户指定参考既有片头时，先读取其实际结构与声画安排，再迁移适合本集的部分。

### 2. 先生成片段与旁白配套的文本结构

1. 第一份创作产物必须是可讨论的纯文本结构，保存为 `edits/<editId>/planning/intro-plan.md`。同一步完成具体选片、顺序编排和旁白写作，不能只给抽象分段、旁白空位或待选素材清单。
2. 稿件包含完整连读旁白与按剪辑顺序排列的选段表。每段写清实际选用画面、当前正文时间码或源文件及入出点、预计时长、原声／静音配旁白／音乐留白安排；原声写实际摘录，新增旁白写完整文案，并明确接入正文的位置。
3. 预计片头位置与当前正文位置分别标注，写明时间单位或帧率。时长从实际选段、旁白语速和衔接估算，不预设固定总长，不照搬参考片头或上一集的时长。
4. 具体选段应核对画面与素材事实。原声以当前已审字幕和实际语音为依据，不能把润色后的文案标成现场原声；句内截取、跳接和需要试听的落点应明确标注。画面与旁白对应，不凭素材显示名补地点或经历。
5. 旁白点出本集的吸引力，原声让观众感受到现场；保留完整经历在正文展开的空间。声画接点要具体，例如旁白提到某种体验后接对应反应，最后一句原声引出接下来的延时画面。

### 3. 可复用的参考结构

1. **航拍＋旁白引入：**用有代表性的风光建立地点与最初印象，留出自然停顿。
2. **静音 VLOG＋旁白展开：**从远景进入地面经历，用具体片段对应旁白里的发现。片头复用的 VLOG 片段可以静音并换用新增旁白字幕；这一处理只作用于片头副本，不改变正文声音、素材口播事实或粗剪口播保护。
3. **原声精选：**让现场发现、对话、反应与趣事接过叙述，按内容组织节奏，避免只罗列景点。旁白结束后交还现场声音，不同时叠压两套讲话。
4. **延时收尾并接正文：**优先让最后一段原声自然引出延时中的变化，再以音乐、必要的片名和画面留白完成收束，明确切入正文的片段。

以上是参考结构，随本集实际内容和用户意图调整。缺少合适航拍、延时或原声接点时，应选用已有素材安排替代衔接，不为套结构假设素材存在。地点、文案、片段数量和时长不沿用上一集。

### 4. 交互修改，再进入实际剪辑

1. 先围绕同一份文本结构讨论引子、选段、旁白和节奏，修订时同步更新关联画面、文案和时长。文本讨论不等于已经生成配音、插入片头或确认完整时间线。
2. 结构获认可后，按具体剪辑任务完成片头、声音和正文衔接；这属于既有人工与 Agent 交互剪辑流程，不新增自动片头 capability，也不要求先生成 `script/current.json` 或全片旁白框架。
3. 实际剪辑后以时间线回读结果更新片段与字幕位置，复核旁白／原声切换和接入正文的效果，再由人工确认完整时间线，定稿剩余旁白与字幕。

## 按需旁白

1. 正文的新增旁白只用于航拍、延时段落；正文地面游览、人物交流和生活片段依靠现场口播与同期声推进。片头的旁白范围按上面的片头方案执行，允许用于航拍与已明确静音的 VLOG 复用片段；不能叠压仍需保留的现场讲话。
2. 航拍与延时根据实际需要补充背景、连接或事后认识，允许留白；没有字幕不等于需要旁白，不要求每段风光都配解说。
3. Agent仅对需要旁白的段落提供对应时间范围和简短文案，依据当前完整时间线的实际可用时长编写，内容与画面、已有事实及真实经历相符。经人工审查后定稿，无需生成全片逐镜旁白框架。

## 收尾

1. 用户在达芬奇中剪辑完成，进行照片音效的补齐
2. 进行非全屏素材背景模糊效果的应用
3. 片头插入或正文调整后，以最终时间线的实际片段位置和源素材范围复核已有字幕，修正错位；不得直接沿用插入片头前的字幕时间。
4. 检查实际保留现场语音却缺少字幕的片段，生成一个SRT，仅补齐这些现场语音字幕；纯视觉且未配旁白的片段没有字幕不算遗漏。
5. 新增旁白字幕按最终时间线单独生成SRT，供用户导入，与现场语音补字幕分开处理；没有新增旁白时跳过。
