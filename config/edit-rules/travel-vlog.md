# 旅行VLOG剪辑规则

流程：正文粗剪 → 人工精剪 → 短片头 → 按需补旁白 → 字幕与收尾。

## 初版剪辑框架

1. 读取理解本集范围内的编年史，生成剪辑框架文本，按天、重点时间、行车、航拍和关键事件组织。使用`SubAgent`，切分按照天，但不是每天一个，而是按照150个事件左右为阈值拆分几天是一个包！
2. 素材必须大致按照时间顺序排列，但是行车部分有额外规则：
    1. 行车部分，由于包含口播部分/第一视角行车/无人机跟车，所以可能需要按照节奏，进行更合理的编排，比如如果同时有无人机跟车和非口播行车素材在一个时间窗口重复，优先使用无人机跟车素材
    2. 行车之外，同一个事件中不同类型的视频，航拍要聚在一起排列插入在普通视频之中，照片要聚在一起排列在最后
3. LLM生成文本稿件，之后交给人工审查：
    1. 稿件参考文档末尾的附录`附录-剪辑框架模板`
    2. 条目尽可能详细，但主表必须便于人工审查：`事件 / 时间 / spans / 叙事` 只写人能快速判断的素材概况，不写代表 spanId、不重复 eventId/routeId/source window 等证据索引，也不写任何具体素材主键
    3. `spans`列必须写可审查的素材类型数量和视频语音拆分，格式参考：`共28段：行车13（有语音5/无语音8）、航拍7、普通视频4（有语音2/无语音2）、照片4`；不能写“高密度素材组 / 多段 / 少量 / 含口播”这类模糊概括
    4. `叙事`列只写素材的客观画面/声音总结，不写“保留 / 优先 / 插入 / 加速 / 静音”等后续剪辑指导
    5. `全片章节`只做宏观概览，`分段操作稿`是给 material.recall 的唯一分段 handoff；不要另写`beat 边界索引`
    6. 尽可能将有效片段添加，不要擅自过多剔除

## 交互式粗剪

1. 根据剪辑框架的定稿，进入素材召回阶段：
    1. 使用`SubAgent`，切分按照天数粒度，但不是每天一个，而是按照2000个span左右为阈值拆分几天是一个包！
    2. 当遇到口播和纯视觉窗口的重叠时，优先选择口播窗口
    3. 源于同一个原始素材的，没有口播的行车Span，首先要按照画面语义去重，然后只能最多保留三段
    4. 所有没有口播的行车类型Span，直接静音
    5. 超过5秒的静音行车片段，通过整数倍加速压到10秒之内，最大倍率四倍，如果脚本无法实现，就试试ComputerUse，反正已经分好颜色组了
2. 根据最终结论，在达芬奇剪辑工程内，生成对应的时间线
3. 根据当前时间线，根据已有的口播字幕映射出一个SRT，供用户导入，辅助剪辑
4. 人工和LLM针对时间线，交互式修改，直到正文基本定稿，人工确认后，进入短片头设计

## 短片头

1. 正文基本完成后，从实际入选内容中提炼精彩预告，以约30秒为参考，具体长度服从内容与衔接，不强制凑时长。
2. 兼顾有代表性的风光高点与有趣的现场经历，用简短表达交代本集特点并自然接入正文；保留完整经历在正文中展开的空间。
3. 片头可以跨时间精选、复用正文素材，正文仍遵循原有的真实经历顺序。Agent给出可审查的片头方案：按建议顺序列出正文时间码或源文件及入出点、预计时长、原声／旁白安排，以及接入正文的位置。
4. 片头方案在现有人工与LLM交互剪辑环节中审查和完成，不视为已有自动片头生成能力。片头及其与正文的衔接完成后，由人工确认完整时间线，再定稿需要补充的旁白。

## 按需旁白

1. 片头和正文的新增旁白均只用于航拍、延时段落，不延伸覆盖其他类型画面，也不覆盖已有口播；地面游览、人物交流和生活片段依靠现场口播与同期声推进。
2. 航拍与延时根据实际需要补充背景、连接或事后认识，允许留白；没有字幕不等于需要旁白，不要求每段风光都配解说。
3. Agent仅对需要旁白的段落提供对应时间范围和简短文案，依据当前完整时间线的实际可用时长编写，内容与画面、已有事实及真实经历相符。经人工审查后定稿，无需生成全片逐镜旁白框架。

## 收尾

1. 用户在达芬奇中剪辑完成，进行照片音效的补齐
2. 进行非全屏素材背景模糊效果的应用
3. 片头插入或正文调整后，以最终时间线的实际片段位置和源素材范围复核已有字幕，修正错位；不得直接沿用插入片头前的字幕时间。
4. 检查实际保留现场语音却缺少字幕的片段，生成一个SRT，仅补齐这些现场语音字幕；纯视觉且未配旁白的片段没有字幕不算遗漏。
5. 新增旁白字幕按最终时间线单独生成SRT，供用户导入，与现场语音补字幕分开处理；没有新增旁白时跳过。
