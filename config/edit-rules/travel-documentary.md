# 旅行纪录片剪辑规则

## 初版剪辑框架

1. 读取理解现有的编年史，生成剪辑框架文本，按天、重点时间、行车、航拍和关键事件组织。使用`SubAgent`，切分按照天，但不是每天一个，而是按照150个事件左右为阈值拆分几天是一个包！
2. 素材必须大致按照时间顺序排列，但是行车部分有额外规则：
    1. 行车部分，由于包含口播部分/第一视角行车/无人机跟车，所以可能需要按照节奏，进行更合理的编排，比如如果同时有无人机跟车和非口播行车素材在一个时间窗口重复，优先使用无人机跟车素材
    2. 行车之外，同一个事件中不同类型的视频，航拍要聚在一起排列插入在普通视频之中，照片要聚在一起排列在最后
3. LLM生成文本稿件，之后交给人工审查：
    1. 稿件参考文档末尾的附录`附录-剪辑框架模板`
    2. 条目尽可能详细，但主表必须便于人工审查：`事件 / 时间 / spans / 叙事` 只写人能快速判断的素材概况，不写代表 spanId、不重复 eventId/routeId/source window 等证据索引，也不写任何具体素材主键
    3. `spans`列必须写可审查的素材类型数量和视频语音拆分，格式参考：`共28段：行车13（有语音5/无语音8）、航拍7、普通视频4（有语音2/无语音2）、照片4`；不能写“高密度素材组 / 多段 / 少量 / 含口播”这类模糊概括
    4. `叙事`列只写素材的客观画面/声音总结，不写“保留 / 优先 / 插入 / 加速 / 静音”等后续剪辑指导
    5. `全片章节`只做宏观概览，`分段操作稿`是给 material.recall 的唯一分段 handoff；不要另写`beat 边界索引`
    6. 尽可能将有效片段添加，不要擅自过多剔除

## 交互式粗剪

1. 根据剪辑框架的定稿，进入素材召回阶段：
    1. 使用`SubAgent`，切分按照天数粒度，但不是每天一个，而是按照2000个span左右为阈值拆分几天是一个包！
    2. 当遇到口播和纯视觉窗口的重叠时，优先选择口播窗口
    3. 源于同一个原始素材的，没有口播的行车Span，首先要按照画面语义去重，然后只能最多保留三段
    4. 所有没有口播的行车类型Span，直接静音
    5. 超过5秒的静音行车片段，通过加速压到5秒之内
2. 根据最终结论，在达芬奇剪辑工程内，生成对应的时间线
3. 人工和LLM针对时间线，交互式修改，直到阶段性定稿，人工确认进入下个阶段

## 字幕和旁白

1. 用户在达芬奇中，使用达芬奇的能力将口播部分识别字幕
2. 对于整个timeline，根据视频内容，首先生成旁白框架文档：
    1. 格式参考文档尾部的“附录 - 旁白生成框架格式参考”，但以下列规则为主
    2. CLIP描述匹配到最接近的span，使用其中的视觉描述，而非MaterialPatter，但最终需要生成为自然的中文语句
    3. 有字幕的CLIP为口播CLIP，没字幕的为需要写旁白的CLIP
    4. 相邻的口播CLIP，可以按照该相关性合并描述；多 clip 口播 pack 只写 pack 摘要和 `clips：起止范围`，不要在 `clips` 下逐 clip 展开口播细节。
    5. 相邻连续且属于同一 confirmed chronology event 的行车/开车无口播CLIP，先合并为一个pack，给出整体视觉总结（包括行程、道路、山体、江河湖泊、植被、村镇和天气路况的归纳），然后给出每一条子CLIP的描述；子CLIP描述必须保留 clip 之间的具体差异，不能把 pack 总结改成“先/继续/最后确认 A、B、C 之间的关系”复制到每一条。
    6. 航拍CLIP，先按相邻关系和 confirmed chronology event 合并为一个pack，给出整体视觉总结（包括编年史事件、机位变化、地貌、水文、道路、村寨、云雾或运动变化），然后给出每一条子CLIP的描述；航拍定位可以使用对应编年史事件作为语境，但子CLIP仍要写出实际飞行位置/视域内的山、水、植被或道路特征。
    7. 相邻照片合并成照片序列，给出整体描述
    8. 相邻、相关的延时摄影可以合并成一个，并给出整体描述，但主要要按照编年史事件，延时摄影都必然有编年史
    9. 每个需要后续生成旁白字幕的无字幕非照片 leaf CLIP，都必须使用当前 CLIP 自己的 GPS / GPX / reverse-geocode 地理上下文；行车子CLIP按当前 clip 源时间中点取定位，不得复用 pack 的整段路线。正文只写可读定位锚点，例如 `（定位：八宿县然乌镇·怒江72拐；然乌湖、帕隆藏布上游冰川湖谷和雪线山坡）`；禁止在正文输出裸 `坐标：lng,lat`、`GPX±Ns`、`机内GPS`、`GPS匹配` 等审计噪音，经纬度、来源和匹配误差只保留在 packet / 审计 JSON 里。
    10. 定位括号里的地貌、水文、道路和植被要做语义去重：前面已经有怒江、澜沧江、金沙江、然乌湖、纳灰河、伶仃洋等命名水体时，不再追加“江河湖泊”；已经有怒江大峡谷、崖壁、峰丛、山口等地貌时，不再追加“峡谷崖壁”；已经有常绿阔叶林坡、云南松林带、针叶林坡、草甸或灌丛时，不再追加泛化植被。禁止写“林带植被”；能从地点、季节、海拔带和画面线索推断时，写成具体植被，例如 `干热河谷灌丛、云南松和针阔混交林`、`高山针叶林、杜鹃灌丛和冷杉林线`、`湖岸草甸`，不能确认时省略。
    11. 反向地理编码命中的公司、店铺、卫生室、村委会、加油站、充电站、停车场等 POI 不能进入标题、整体句或旁白素材；只在审计数据里保留。正文定位应改写为真实旅行节点、道路方向、村寨、桥隧、水系或地貌锚点。
    12. 道路、桥梁、隧道、互通、收费站、跨江/跨海通道等线性交通设施可以作为可读定位锚点；如果周边 POI 只以“某通道项目部 / 管理中心 / 停车场 / 观赏点”出现，只能抽取其中真实交通设施名（如“深中通道”），不能把 POI 全名写进正文。
    13. 车身颜色不是行程事实；除非当前 CLIP 的视觉证据明确且确有叙事必要，默认写“车辆 / 车流 / 车队”，不得杜撰或反复突出“黄车、白车、黑车”等车身颜色。
    14. 启用一个subagent进行编写
    14. 完成后，供用户审查和修改
3. 用户确认框架后，进一步生成最终的字幕审查稿，是一个markdown表格：
    1. 字幕风格需要参考当前剪辑项目指定的`风格档案`，真相来源以当前 post-lock Resolve timeline / clip packet 为准，必须参考每个 CLIP 或 clip 序列组的真实时长来生成字幕。
    2. 产物表格固定三列：`对应旁白框架条目（若合并写多个）`、`事件和可读位置信息`、`生成旁白字幕`，参考文档末尾的`附录 - 最终字幕审查稿格式参考 `，但字幕风格仍然参考`风格档案`
    3. 对于行车/开车/航拍/延时序列，先综合判断 pack 的整体叙事动机，再按每个需要旁白的 CLIP 分开编写；每个 CLIP 原则上分配一句字幕，并保持前后逻辑连续。
    4. 短 CLIP 必须写短句：3-5 秒只写一个可读短句，不塞完整解释；长 pack 的信息通过多条 CLIP 字幕连续推进。
    5. 有字幕的口播 CLIP 不重复生成旁白，只能作为前后承接参考；照片和照片序列均不生成字幕，若保留表格行则写 `不生成字幕`。
    6. `事件和可读位置信息` 列只写叙事可用地名、路线方向、真实旅行节点，以及可从定位推算出的山体、江河湖泊、植被、桥隧和地貌特征。反向地理编码命中的公司、店铺、卫生室、村委会、路边设施、小型水库等附近 POI 只能留在审计数据里，不能当作事件名、目的地、路线终点或字幕素材；但道路、桥梁、隧道、互通、收费站、跨江/跨海通道等交通设施专名应保留为可读锚点。
    7. 路线表达优先写成自然方向，例如“江门开平之后，往广西灵山方向”“南宁往百色方向”“进入贵州后的山地高速”；不要直接复制完整反查地址或 POI 名。
    8. 字幕正文只写观众能听懂的自然中文旁白，不写数据库痕迹、GPS 细节、标签串或硬造词；禁止 `雨后湿滑、高速路面、道路延伸` 这类标签堆叠，也避免 `云天下` 这类不自然表达。
    9. 启用一个 subagent 进行编写。
4. 按照完成的审查稿，生成最终的SRT字幕，并提示用户手动导入到达芬奇

# 附录 - 旁白生成框架格式参考
主题：丙察察格聂南线子梅垭口穿越，自驾穿越与风光摄影
季节：五一前后，滇藏川高原春末夏初
下面是目前排好的粗剪时间线，格式规则为：
1. 顶层有序列表代表 timeline 中的叙事单元，可以是单个 CLIP、口播 pack、行车 pack、航拍 pack、照片序列或延时序列。
2. 顶层标题直接用类型前缀表达，例如 `口播 pack`、`行车 pack`、`航拍 pack`、`照片序列`、`延时`、`延时序列`；Markdown 列表结构里不再额外使用旧版括号符号。
3. `整体` 用来描述 pack 的段落级理解，包括路线、空间关系、时间变化、编年史事件或现场氛围。
4. `clips` 子列表保留每条 Resolve CLIP 的边界和描述；后续字幕审查稿按这些子 CLIP 继续写。
5. 单个无字幕 CLIP 也使用同样结构，只是 `clips` 下只有一条。
6. 照片序列可以只写整体描述，不强制逐张写。
7. 延时序列必须带编年史事件 / 地点语境，不能只按画面相似合并。
8. 正文描述要写成自然中文场景句，不写 `雨后湿滑、高速路面、道路延伸` 这类标签串。
9. 需要生成旁白字幕的无字幕非照片 leaf CLIP，行尾可以写 `（定位：可读地名/道路/村寨锚点；山体/命名水系/具体植被/道路地貌特征）`；不得写裸经纬度、GPS来源或匹配误差。
10. 定位括号服务于下游字幕判断，只保留可读锚点；公司、村委会、加油站、充电站、卫生室、卫生间、酒店、民宿、停车场等误命中 POI 不进入正文。
11. 定位括号不得堆叠重复泛类：不要写 `怒江大峡谷北段、碧罗雪山与高黎贡山夹峙的江湾和崖壁，江河湖泊、峡谷崖壁、林带植被`；应改为 `怒江大峡谷北段、碧罗雪山与高黎贡山夹峙的江湾和崖壁，干热河谷灌丛、云南松和针阔混交林`。若具体山河地貌已经覆盖水文或崖壁，就只补充尚未覆盖且可确认的植被 / 道路 / 村镇信息。
12. 行车 pack 的整体句必须归纳子 CLIP 中共同出现或逐步变化的地貌、水文、道路、植被和村镇线索，不得只拼接首尾两条；行车子 CLIP 的定位按当前 clip 中点附近的实际位置写，不能直接复用 pack 标题或整段路线。
13. 车身颜色只有在画面确证且需要区分主体时才写；默认写“车辆 / 车流 / 车队”，不要把行程描述写成“黄车 / 白车 / 黑车”观察。
14. 多 clip 口播 pack 只写摘要和 `clips：起止范围`，不逐 clip 展开。
