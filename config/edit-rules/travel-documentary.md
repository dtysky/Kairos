# 旅行纪录片剪辑规则

## 初版剪辑框架

1. 读取理解现有的编年史，生成剪辑框架文本，按天、重点时间、行车、航拍和关键事件组织。使用`SubAgent`，切分按照天，但不是每天一个，而是按照80个事件左右为阈值拆分几天是一个包！
2. 素材必须大致按照时间顺序排列，但是行车部分有额外规则：
  1. 行车部分，由于包含口播部分/第一视角行车/无人机跟车，所以可能需要按照节奏，进行更合理的编排，比如如果同时有无人机跟车和非口播行车素材在一个时间窗口重复，优先使用无人机跟车素材
  2. 行车之外，同一个事件中不同类型的视频，航拍要聚在一起排列插入在普通视频之中，照片要聚在一起排列在最后
3. LLM生成文本稿件，之后交给人工审查：
  1. 稿件参考文档末尾的附录`附录-剪辑框架模板`
  2. 条目尽可能详细，但主表必须便于人工审查：`事件 / 时间 / spans / 叙事` 只写人能快速判断的素材概况，不写代表 spanId、不重复 eventId/routeId/source window 等证据索引，也不写任何具体素材主键
  3. `spans`列必须写可审查的素材类型数量和视频语音拆分，格式参考：`共28段：行车13（有语音5/无语音8）、航拍7、普通视频4（有语音2/无语音2）、照片4`；不能写“高密度素材组 / 多段 / 少量 / 含口播”这类模糊概括
  4. `叙事`列只写素材的客观画面/声音总结，不写“保留 / 优先 / 插入 / 加速 / 静音”等后续剪辑指导；后续召回与处理建议统一写到`给 material.recall 的执行索引`
  5. `全片章节`只做宏观概览，`分段操作稿`是给 material.recall 的唯一分段 handoff；不要另写`beat 边界索引`
  4. 尽可能将有效片段添加，不要擅自过多剔除

## 交互式粗剪

1. 根据剪辑框架的定稿，进入素材召回阶段：
  1. 使用`SubAgent`，切分按照天数粒度，但不是每天一个，而是按照2000个span左右为阈值拆分几天是一个包！
  2. 当遇到口播和纯视觉窗口的重叠时，优先选择口播窗口
  3. 源于同一个原始素材的，没有口播的行车Span，首先要按照画面语义去重，然后只能最多保留三段
  4. 所有没有口播的行车类型Span，直接静音
  5. 超过5秒的静音行车片段，通过加速压到5秒之内
2. 根据最终结论，在达芬奇剪辑工程内，生成对应的时间线
3. 人工和LLM针对时间线，交互式修改，直到阶段性定稿，人工确认进入下个阶段

## 收尾

1. 根据粗剪定稿，生成源语音字幕
2. 对于没有语音的段落，根据视频内容，生成旁白稿，需要参考指定`风格分析`结果，最终由人审查
3. 审查结束后，生成完整字幕，并应用到达芬奇时间线上

## 给 material.recall 的执行索引

- 每个 FW 段按 `分段操作稿` 的 FW beat 顺序召回，禁止跨段回捞，除非为补开场、补总结或补同一地点的航拍成果，并在召回结论中写明原因。
- 每个 FW 段先召回核心事件，再召回连接 route；route 只提供代表窗口、路况证据和口播，不作为无差别素材池。
- 每个核心事件内部排序建议：普通视频动作 -> 航拍组插入 -> 照片组收尾；行车事件例外，优先按“口播/路况/航拍跟车/地理证据”组织。
- 静音候选：无口播航拍、无口播重复第一视角、照片、纯环境 broll。
- 不静音候选：有 transcript 的路线说明、危险路况反应、出发/总结、人物决定、桥梁/垭口介绍。
- 加速候选：无口播普通高速、普通山路重复窗口、返程长 route；只限 drive / aerial。
- 不加速候选：source speech、桥梁/垭口仪式点、危险路况、雪夜硬上、炸机找回、最终雪山成果。
- material.recall 输出在 `material-slots.json` 的 `chosenSpanIds/treatments` 中保留可溯源素材主键；`edit-framework.md` 不写 chronology/event/route/gap/span/asset id。
