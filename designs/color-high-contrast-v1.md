# 逆光／大光比首轮标定

2026-11-06 用户认可使用 C3907、C5080 与 DJI_20261006062418_0963_D 三条原片测试。当前范围只包含逆光／大光比分类证据，不包含曝光、白平衡、降噪、美肤或其它修正。

## 用户确认的排除规则

2026-11-06 用户明确：**夜景不纳入逆光／大光比**。这属于类别适用范围的硬排除，覆盖广域亮暗反差及小光源两条路径，不仅排除车灯/路灯。无论数值多高、持续多久，已确认夜景均不产生该类候选；测量值可保留审计，但不能表述成该类技术阳性。

夜景语义沿用素材级描述与 GPS/校正拍摄时间的既有判断，不能只因拍摄时间是晚上就把正常照明室内当作夜景。晨昏不因此排除；日夜未知、冲突或片内跨越时待复核，不默认为非夜景。竖屏、人物口播、过曝、噪点的既定规则与优先级不变。

试验中用独立 `applyHighContrastScenePolicy` 消费已经确认的夜景/非夜景/未知上下文，保留原始像素测量；不新增 Analyze 字段或模型请求。正式大光比分类尚未接通，后续接入必须遵守该排除规则。本轮 C5067 的夜景标签来自测试帧复核，不能冒充其缺失的正式 Analyze 事实。

排除规则验证：C5067 原始两路径汇总仍为 `candidate`，应用夜景规则后为 `excluded`；三条指定非夜景候选保持 `candidate`。结果另存同轮夹具的 `night-exclusion-policy.json`，原始测量不改写。新增持续广域反差/光晕双路径排除与未知上下文回归，测量和分类相关 17 项测试通过，根仓与 Console 构建通过。此策略只限定大光比试验的适用场景，不提前启用正式分类。

## 本轮计划

1. 使用既有原片色彩解释及显示 LUT，独立解码全片时间采样；太阳本身不要求占大面积。先保存可审计的亮暗区域、光源候选和持续区间，不由文件名或既有技术标签返回结果。
2. 分别检验广域亮暗区域与紧凑强光源两条候选路径。小光源的光晕、周边背景与暗前景必须一并检查；点状车灯、路灯不能独自触发。纯亮度不能证明物理光源身份或拍摄意图，歧义保留为候选/复核。
3. 使用原三条候选及普通日景、夜间车灯、既有过曝/噪声样本对照。先检验像素测量与空间区域；通过后再决定正式分类接入门槛。C5080 用于验证人物口播主类优先；竖屏、过曝、噪点优先级也保持既有约定。

## 输入边界

- 选样记录位于 Git 忽略的测试项目 `.fixtures/backlight-candidates-1793952849918/candidates.json`。用户同意测试这些候选，不等于对每帧、每个区间都已做出人工技术标注。
- 原片只读，记录内容哈希、色彩解释来源、LUT 哈希与抽帧时间。Sony 两条由 XML 检出 S-Log3；DJI 0963 目前沿用 root 声明的 D-Log，审计中必须保留 root-fallback 来源。
- 沿用 `store/color-inputs.json` 的素材级事实边界，不改 Analyze、ASR 或窗口规则，不把历史 spans 当成新的正式 Analyze 报告。没有当前报告的样本只能验证独立检测与测试夹具中的分类规则，不能宣称已完成正式 prepare 或真实 Resolve Group 验收。
- 以显示亮度指标描述反差，不把 LOG/显示 RGB 数值比称为物理曝光档数。低分辨率全图统计可能丢失极小太阳核心，本轮技术采样采用较高分辨率并记录尺寸；这与 Analyze 的抽帧尺寸无关。

## 验收边界

首次试验允许结论为漏检、误报或不确定，不能为命中三个文件而增加文件名规则，也不能只展示成功帧。输出每个完整样本的候选占比、连续区间、区域坐标、测量值和明确限制。纯白/黑白物体、细碎纹理及照明反差之间存在歧义；上下文仅辅助排除，不从模型的“逆光/大光比”文字直接产生阳性。

下一项仅在测试结果上做消融：保留相同像素测量和所有阈值，以 `broad-regions` 单一路径重新汇总连续区间，小光源信息只留审计。不得把这次在已见样本上的误报排除宣称为独立验证集准确率。正式分类仍未接入；1 fps 下的区间为采样区间，不是逐帧定位。

DJI 0097 日间航拍对照有亮天空/云与阴影山坡的明显反差；其命中只能作为待判定的边界例，不能因起初叫“日景对照”就标为误报。C4248 的晨昏亮天空与暗山体同样存在反差，其已确认噪点类别仍优先。C5080 的出镜口播优先级不变，但本轮样本缺少当前正式 Analyze 报告，不宣称已验证其正式分类或 Resolve 分组。
